## 上传协议与资源预算

1. 登录获取现有 Socket 绑定的 Bearer Token。
2. `POST /api/media`：`Authorization: Bearer …`、`Content-Type: image/png`（或允许的音频 MIME）、`X-Uni-Media-Event: chat image`；请求体为原始文件字节，无 multipart 封装、无 Base64 扩容。
3. HTTP 返回 `{ticket, expiresIn:120}`。随后继续使用原 Socket 事件，`base64` 字段改传此 ticket；聊天仍包含 `clientMessageId`。成功写库后才确认及广播。
4. ticket 绑定 Socket、Token、用途及聊天房间。切换身份、退出、断线、密码重置会撤销；过期拒绝。聊天重试使用同一业务 ID，重新上传后仍由数据库唯一 ID 去重。
5. 非聊天 ticket 使用一次；聊天 ticket 成功后释放，写入失败时保留至到期供同一请求重试。HTTP 完成和异步解码完成时再次校验会话与房间。

|资源|限制|
|---|---|
|聊天/帖子/背景图片|5 MiB|
|头像/表情图片|2 MiB|
|语音|3 MiB，客户端录制最多 120 秒；服务端校验声明时长 0–120 秒|
|HTTP/旧 Socket 解码任务|合计同时最多 2 个，忙时受控拒绝|
|请求持续时间|15 秒总期限；客户端 20 秒取消保护|
|上传请求配额|每用户 30 次/分钟；限流状态最多 10,000 项|
|待确认 ticket|每 Socket 最多 4 个；全局 Base64 字符总量 32 MiB；120 秒有效，访问时清理过期项，退出立即清理|
|图片解码|每边最多 8192、总计 1600 万像素、最多 100 帧、5 秒处理超时|
|解码器|sharp 缓存关闭，单任务线程并发设置为 1|

预算针对上传流水线：两个请求体约 10 MiB、两个 RGBA 解码结果最多约 128 MB、ticket 字符串最多 32 MiB 字符（字符串实现可能占约 64 MiB），另有转换与原生库开销。**这不是整个 Node 进程的内存硬限额或实测峰值保证**；已有聊天 Base64 历史缓存、数据库和广播另占内存。生产应配合反向代理连接限额和进程资源监控。没有设置无限 Socket 缓冲。

持久存储尚无每用户累计磁盘配额；本次限制单文件、上传频率与同时处理资源，未擅自清理真实内容。

## 会话与阅读契约

- 继续采用 Socket 生命周期绑定 Token。传输恢复不等于登录恢复，密码重置/退出撤销的 Token 永不用于自动重登。
- 未确认消息 ID 仅保留于本页内存；重新登录并进入原会话后人工核对、重试相同请求可去重。刷新页面不提供持久离线发件箱。
- 重新选房间可取得最近 300 条数据库历史，之前的分页接口仍可读取更早数据；本轮未添加无限滚动入口。
- 已读请求：`{roomId, cursor:{id,timestamp}}`。时间戳必须与该房间数据库消息一致；按 `(created_at,id)` 比较，旧设备回执不回退。
- 新发送消息的时间戳按房间单调推进，避免同毫秒随机 ID 排序使后写消息落在已读游标之前。已有时间戳不重写。
- 客户端只提交实际可见、完全进入消息区域的行。超高消息、未加载成功图片采取保守处理；不声称能证明人眼阅读，也不阻止用户修改客户端主动标记自己的授权消息。

## 安全核查与公开推送阻断

### U11 · 历史聊天数据，需优先确认/处置

本地确认 `92d66aa:chat-history.json` 仍在当前 HEAD 可达历史中：2,323,582 字节、287 条有正文、用户名及时间戳的记录，其中 10 条包含媒体 Data URL。仓库可匿名查看。检查只输出计数，不复制正文、用户名或媒体到报告/新提交。

常见密钥格式与邮箱正则没有命中，**这不能证明没有敏感数据**。本轮未建立这些聊天/图片均为合成数据或已获得公开授权的依据，也不能仅凭结构断言每条都是真实私人聊天。

**处置状态：公开推送阻断待核实。** 维护者应优先在受控本地环境确认来源与公开授权；若包含真实私人信息，应立即评估访问限制、涉密凭证撤销及另行授权的历史清理。当前忽略规则不能移除历史对象。本轮不改写历史、不删除远端记录、不强制推送；本地修复保留未提交，等待单独决定。
