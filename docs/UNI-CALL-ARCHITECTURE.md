# Uni Call · 架构与安全

Uni 5.6 的一对一语音通话从私聊工具栏或对方资料页发起。接听需要用户主动操作。已打开的页面可以显示来电，悬浮胶囊在站内视图切换期间保留通话。页面刷新、关闭、浏览器挂起及锁屏的支持取决于平台，见测试报告。

|层|实现|
|---|---|
|网页与认证|现有 Express 和 Socket.IO。服务端登录成功响应提供 `features.uniCall`，前端据此显示通话入口。|
|信令与生命周期|`lib/uni-call.js` 确定双方、绑定设备、分配 Call ID、管理时限及协商轮次。详见 [信令协议](UNI-CALL-SIGNALING.md)。|
|媒体|`public/scripts/uni-call.js` 创建一个浏览器 PeerConnection，使用浏览器的音频协商、ICE 和 DTLS-SRTP。实际媒体经直连或 TURN，不进入 Node 消息接口。浏览器测试协商为 Opus。|
|交互|浅色和深色功能材质、非模态来电、电话操作与持久的浮动胶囊。来电不抢当前输入焦点，已打开其他模态时仍适用该模态的焦点约束。|
|历史|同一 Call ID 最多一条现有 SQLite 私聊消息。媒体内容和信令不持久化。|

## 媒体、设备与网络

首次发起时先申请麦克风，再发起信令；接听方只在主动点击接听后请求麦克风。静音以 `MediaStreamTrack.enabled` 控制发送。设备切换通过 `RTCRtpSender.replaceTrack` 完成，成功后停止旧音轨。若浏览器可用，显示 `setSinkId` 列出的输出设备或 `selectAudioOutput` 选择器。输出音量控件在媒体元素支持调节时显示，其他环境使用系统音量。音频自动播放失败时出现手动播放按钮。

回声消除、降噪、自动增益按 `getSupportedConstraints` 请求为首选。浏览器决定最终启用情况。对方语音活动来自远端流的 Web Audio RMS 采样。网络质量每 4 秒读取可用 RTT、抖动、相邻统计的丢包率和候选类型。无可用统计时显示未知。质量提示阈值为 Uni 的工程选择。

在两端都保持授权时，ICE 失败或持续断开触发有限重试。角色保持固定，由主叫生成新 Offer。信令断开时双方暂停发送麦克风音轨。旧 Socket 凭证立刻按现有规则撤销。同一页面重新登录同一账号且保持原端点恢复密钥，才可在 18 秒内接续。失效、超时、结束或账号变更均清理媒体。重连期间浏览器可能继续显示麦克风占用指示，轨道处于禁用状态，窗口期后停止。刷新页面会丢失只保存在内存中的恢复信息。

## 数据兼容性

无需 SQLite 结构迁移。现有 `messages` 的 `type` 是开放 TEXT，新增 `call` 值。主键为 `call:<UUID>`，`content` 为有限结果码，`duration` 为整数秒，`room_id` 为两个账号对应的现有 `dm:` 会话。数据库插入先于广播，冲突时不重复写入，等待中的通话和候选都保存在进程内。

通过服务端状态生成结束原因。通话起点在双方完成 SDP 协商并分别确认媒体连接后，由服务器记时。时长是服务端观察到的会话时长，包括重连等待。WebRTC 直连架构下，服务端不能独立审计浏览器的 RTP 包和用户是否开口。服务重启会失去活跃通话状态，已落库历史可按原私聊分页读取。持续 SQLite 写失败时，释放通话和媒体资源，记一次脱敏故障并重试相同 ID。进程崩溃或反复写入失败仍可能缺少结果。

较早前端旧版本可能将新类型呈现成普通文本结果码。上线时应让前后端版本配对。数据库回退无需删除记录。与所有生产 SQLite 运维一样，按现有备份流程演练恢复。

## 安全审查

|边界|处理及限制|
|---|---|
|冒充、跨账号操作|每个事件检查现有 Socket 账号与密码版本，参与者来自服务端登记。Call ID 本身不赋予访问权。|
|私聊权限与封禁|使用现有私聊授权，并检查双方封禁。账号切换、登出、密码重置和封禁进入终止路径。当前项目未发现独立的用户屏蔽关系表。|
|多设备|一个账号最多占用一场通话，来电最多发送给 16 个现有登录端。首个成功接听端成为唯一接听端，其他端收到关闭状态。|
|信令|只支持一条音频媒体段。限制 SDP 24 KiB、ICE 字符串 1024 字符、轮次及 Offer/Answer 角色。Socket.IO 原有传输限制继续适用。|
|频率|每账号每分钟最多 6 个新呼叫请求，跨设备共享。每 Socket 每 10 秒限 180 个通话操作，进程最多 500 场活跃通话。配额和重放缓存有容量上限。|
|恢复|每端的随机密钥仅向该端发送。恢复同时匹配账号、密码版本和宽限期。已结束或未授权的信令得到受控错误。|
|存储与日志|通话结果只进入原私聊历史。应用不记录完整 SDP、ICE、恢复密钥、TURN 凭据或音频。部署时应同样控制代理流量检查和 TURN 日志。|
|网络隐私|允许直连时，参与者的 ICE 候选可能包含网络地址。若部署要求不向对方暴露直连候选，配置 TURN 后使用 relay 策略并验证。媒体使用 WebRTC 的加密传输，身份与信令完整性仍依赖可信 Uni 服务和 HTTPS。|

## 性能与材质

每场通话每端采用一个 PeerConnection 和至多一个 AudioContext。媒体协商和 ICE 重试沿用连接。语音活动只在前台展开面板每 250ms 更新，统计每 4 秒，连接状态对账每 15 秒。结束时停止本地轨道、关闭连接与音频上下文、移除远端媒体及清理定时器。页面级的设备和 Socket 监听只安装一次。

通话面板的磨砂集中在单一浮动功能层，内含常规控件底色。减少透明度时使用实色，减少动态效果时取消空间转换。此处沿用项目的 [Apple Fidelity 研究](NAPA-APPLE-FIDELITY.md)。没有给通话界面另建 WebGL 路径，也无需改变首页的壁纸折射实现。 [Apple HIG Materials](https://developer.apple.com/design/human-interface-guidelines/materials) · [Apple HIG Motion](https://developer.apple.com/design/human-interface-guidelines/motion) · [W3C WebRTC](https://www.w3.org/TR/webrtc/)
