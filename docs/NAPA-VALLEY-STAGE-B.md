## Stage A · 原版 Sonoma 设计基准

直接从稳定提交获取基准 HTML，使用同一批合成内容、同一浏览器与视口拍摄对照，未以被否决的 Liquid Spectrum 作为视觉参考。

|层级|原版特征|本轮处理|
|---|---|---|
|Atmosphere|`/assets/backgrounds/sonoma.jpg`、10px 景深、浅/深色遮罩|原封保留，不替换为通用渐变或纯色|
|Structure|居中窗口；聊天左侧用户列表；原有首页模块入口；右上搜索/通知入口|保持位置、尺寸逻辑及事件入口|
|Content|聊天/论坛/用户资料的原有信息密度和蓝色 Sonoma 调色|不改气泡、帖子、评论树和资料布局|
|Interaction|居中登录玻璃、输入区、四项移动导航|本轮仅升级这三个区域及现有搜索/通知导航容器的材质|
|Motion|页面 translateZ/scale/opacity 飞入飞出；登录在前、主界面在后|保留空间模型，局部调校登录景深与控件反馈|

观察到的升级机会：原来不同控件的高光接近均匀白边，交互区厚度感不强；输入区与消息内容的前后层级不够明确；移动导航激活背景直接替换，缺少连续选中态。没有把这些判断扩展成重新组织产品导航的理由。

## Stage B · 已实施范围

### 1. 登录玻璃

保持原有单张居中登录卡片、登录/注册表单、切换用户和设置入口。主界面在登录时以 `opacity .58`、适度后移/缩放与 12px 模糊退入后景；窄屏使用 8px。前景卡片保持清晰。

玻璃使用原有透明度变量、上方局部反射、弧形轮廓光、内侧暗边和定向阴影。输入聚焦及登录按钮按压具有独立反馈。原版页面退出与清理机制继续负责动画结束后的隐藏，没有绕过认证或改变登录协议。

登录期间后台聊天区域设为 inert，避免 Tab 焦点落入纯背景。离开登录后恢复。没有把登录替换成宣传页，也没有引入装饰性 Hero。

### 2. 原有导航

保留首页模块按钮、全局搜索/通知位置和移动端四项导航。移动导航只新增一个无交互的 `aria-hidden` 玻璃指示器，在原按钮之间连续移动；原来的点击处理仍是唯一业务入口。

选中态同步 `aria-current`。隐藏、键盘出现、横竖屏或容器尺寸变化时重新测量可见按钮的位置，不重写 U19 的导航高度和 safe-area 算法。

### 3. 聊天输入区

保留原表单、textarea、提及/图片/语音/表情/发送按钮及全部 ID。增加小幅内缩、悬浮玻璃边缘与内外阴影，让输入区与消息阅读面区分开；没有增加聊天横幅、删减消息或改动发送逻辑。

窄屏 textarea 保持 16px，减少 iPhone 自动放大风险。导航底部空间、VisualViewport、中文输入法、幂等发送和失败重试由既有逻辑继续管理。

## 光学设计与实现边界

`public/styles/napa-optics.css` 定义分层材质、边缘反射、低强度冷/暖色散、内部阴影、lens strength，以及以下动效 Token：

|Token|时长|用途|
|---|---:|---|
|motion-enter|420ms|既有首页入口响应|
|motion-exit|320ms|后续退出语义预留，未扩展其他菜单|
|motion-navigate|520ms|登录/背景空间过渡|
|motion-morph|480ms|移动导航指示器|
|motion-press|140ms|输入区与登录按钮按压|
|motion-focus|220ms|输入聚焦、边缘光反馈|
|motion-overlay|360ms|登录景深与局部主题光照反馈|

- **Lensing / Edge Displacement 是视觉近似**：masked gradient rim、内侧明暗错位与曲率处局部光。没有真实改变背景光线路径，更没有把高斯模糊称为真实折射。
- 色散限制在约 1.5px 的轮廓区域，采用低强度冷/暖分量，不作用于文字或图片。
- 新增效果只对指定容器采样背景；不为每个输入框/按钮新增 backdrop-filter。保留旧版未在本轮整治的玻璃层级，不宣称全站合成成本已优化。
- 使用一个委托 pointermove 监听器和一个活跃表面的 RAF；仅进入表面时读取矩形。按时间阻尼，最后一次移动后最多 600ms 收敛，无持续装饰循环。
- 触屏不启动鼠标高光模拟；使用原有及本轮调校的按压反馈。
- 主题响应是玻璃局部的短暂光照移动，**不是全屏 Glass Flood**；完整主题形变尚未实施。
- 原有玻璃滑块仍控制实际透明度与 blur。没有新增保存键或覆盖用户选择；缺省 50%、显式 0% 均保留。
- 遮罩不支持时去掉增强轮廓；backdrop-filter 不支持时使用清晰的不透明浅/深色材质；高对比度减少光学装饰。reduced-motion 关闭新增运动和高光跟踪。

## 可运行本地预览

在项目目录运行：

```sh
node scripts/preview-napa.cjs
```

默认只监听 `127.0.0.1:8856`，可用 `NAPA_PREVIEW_PORT` 指定其他端口。页面上方的独立预览工具条可切换登录/聊天/首页、原版/升级后、浅/深色。

- 升级后登录：`http://127.0.0.1:8856/?scene=login`
- 升级后聊天：`http://127.0.0.1:8856/?scene=chat`
- 原版对照：`http://127.0.0.1:8856/?scene=login&baseline=1`
- 深色登录：`http://127.0.0.1:8856/?scene=login&theme=dark`

预览是**合成客户端演示环境**：不引入 `server.js`，不打开数据库，不提供上传路径，只允许读取受控公开静态资产。登录预填合成账号；消息仅在本页内存回显，不持久化。它不是完整后端联调，不要使用真实账号信息。截图只包含合成数据；原始历史聊天与媒体没有进入预览。

## 验证与验收边界

本轮结果：

- 服务端、两段既有内联脚本、新增光学脚本、预览服务与浏览器检查脚本语法通过。
- `node --test test/mobile.test.cjs test/reliability.test.cjs`：**14/14 通过**，使用校验过的隔离 Node 24.22.1；未再次运行全套测试。
- Stage B Chromium 检查：**18/18 通过，页面脚本错误 0**；覆盖 390/430/768/1366px、浅/深主题、模拟键盘、多行输入、IME、导航、合成登录和发送。
- 原版与原型截图 **10 张**；实际 Chromium 版本为 156.0.4314.50。
- 原有业务 DOM 的 ID 序列一致；既有内联 JavaScript 内容逐字一致。新增全是独立展示增强，没有修改业务事件契约。

结果位于外部 `outputs/napa-stage-b/` 的 `targeted-tests.log`、`stage-b-validation.json`；截图以 `before-` / `after-` 命名，`comparison.html` 提供可拖动对照。浏览器用合成数据检查登录过渡、玻璃滑块、导航、焦点、中文输入法、发送入口及输入区边界。

这些检查只证明本轮局部原型的受测行为。**没有自动进入 Stage E：没有进行全站兼容性验收、真实 Safari/iPhone 键盘、PWA 独立窗口、GPU 性能或完整生产后端端到端验证。** Headless Chromium 使用软件渲染截图，不能据此保证实机帧率。

待负责人确认的视觉重点：

1. 登录时后景的模糊和空间距离是否适当。
2. 控件边缘是否有厚度感，同时足够克制。
3. 输入区悬浮间距与原版信息密度是否平衡。
4. 移动导航的连续选中态是否清晰，整体是否仍能立即识别为 Sonoma。
